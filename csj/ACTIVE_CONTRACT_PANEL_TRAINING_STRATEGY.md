# 活跃具体合约面板（可变邻居）训练策略

状态：拟议，须先通过数据审计与 Pair Probe，才能进入完整路径生成训练。

## 1. 决策摘要

本阶段不再使用 `rb8888`、`i8888` 等连续合约，也不处理换月。训练和生产预测对象都是具体交割月份合约。

每个合约仍以原始六维 `open/high/low/close/volume/amount` 作为 K 线输入。一个预测案例由一条目标合约流和零到多条同品种邻居流组成，模型只生成目标合约的未来路径；“面板”表示可变大小的同期合约集合，不表示必须输入三个合约。

第一版按品种分别实验 `i`、`j`、`jm` 和 `rb`，不跨品种共享一个最终模型。实验顺序固定为：目标单流基线；目标加一个最近交割月份邻居；只有双合约实验通过后，才单独评估第二个邻居。邻居信息是否有效，必须相对相同上下文长度、相同案例集合的目标单流基线做严格配对验证。

## 2. 已知约束

- K 线服务只能查询当前仍在交易的具体合约，不能补取已交割合约历史。
- 当前客户端按已知 `InstrumentID` 查询，不能可靠发现活跃合约全集。
- 服务端对错误参数容忍度低；每次请求必须运行在独立进程中，设置 socket 超时和进程级总时限，超时后主动关闭，不进行无界重试。
- Kronos tokenizer 的输入维度固定为六维；不能把 `K` 条合约流直接拍平成 `6K` 维后继续假设仍可复用原 tokenizer。
- 当前生成接口只接受一条目标合约 token 序列，不能直接消费任意“邻居融合表示”。完整邻居条件生成需要显式适配器和新的推理入口。
- 当前配置的最大上下文为 512 根。是否从 256 延长到 512，必须先由数据覆盖审计决定，不能与面板增益同时混为一个实验变量。

## 3. 领域定义

### 3.1 预测对象

- **目标合约**：调用方要求预测的具体合约；未来标签、生成路径和最终指标都只属于它。
- **邻居合约**：预测时刻仍活跃、与目标合约同品种且合约代码不同的具体合约。
- **有符号月份距离**：`delta_month = neighbor_delivery_month - target_delivery_month`；负数表示邻居交割更早，正数表示邻居交割更晚。
- **最近月份邻居**：在候选邻居中使 `abs(delta_month)` 最小的合约。若两侧距离相同，首版固定选择交割更晚的一侧，避免训练与生产产生不一致的随机选择。
- **面板案例**：同一预测时刻下，一条目标合约合同内历史、零到多条邻居合同内历史，以及目标合约的未来三日标签。

“近月”和“远月”只是邻居相对目标的有符号期限关系，不是两个必须填满的输入槽。P1 只使用一个最近月份邻居；没有有效邻居时路由到独立验证过的 P0 目标单流模型，不构造伪邻居、不复制目标流，也不向 tokenizer 填充假 K 线。

### 3.2 与换月无关

每条输入流从头到尾只属于一个具体合约。案例构造不拼接合约，因此不存在连续合约换月边界、换月跳空或主力切换逻辑。

## 4. 数据采集与留存

### 4.1 活跃合约清单

为每个采集日保存不可变清单，至少包含：

```text
snapshot_at
product
contract_id
delivery_year_month
first_available_bar
last_available_bar
```

清单来源必须明确记录。不能在历史回放时根据未来成交量或未来是否成为主力来选择合约。

### 4.2 原始 K 线快照

- 对清单内每个合约拉取小时 K 线并保存原始响应，不覆盖旧快照。
- 在合约停止交易前完成最终归档，否则服务端之后无法补取。
- 合并快照时按 `contract_id + timestamp` 去重，并校验价格关系、非负成交量、交易日根数和时间单调性。
- 单个请求失败只记录失败，不自动改变参数反复请求。

### 4.3 数据可用性限制

初始语料只覆盖当前活跃合约从上市至今的历史，存在样本量小、期限覆盖不完整和幸存样本偏差。更早的历史时点还可能缺少当时存在、但现在已经交割的更近月份合约，因此不能重建完整的历史面板。

首个完整活跃合约清单快照之前构造的案例必须标记为 `partial_panel`：可以用于探索性训练，但不能用于最终面板验证。生产同口径的验证期从首次完整清单快照之后开始。系统需要持续归档，才能逐步形成包含已退市合约的自有历史库。

## 5. 面板案例构造

对预测时刻 `t` 和目标合约 `c`：

1. 只使用 `timestamp <= t` 的已完成 K 线。
2. 从 `t` 时刻保存的活跃合约清单中建立同品种邻居候选集；没有当日清单的历史案例只能标为 `partial_panel`。
3. 按 `abs(delta_month)` 升序排列候选；距离相同时先选交割更晚的一侧。P1 只取排序第一的一个邻居。
4. 目标与选中的邻居分别截取相同长度 `L` 的合同内上下文。
5. 所有已选流必须按真实时间戳对齐；首版遇到任一已选流缺根即丢弃配对案例，不做前向填充。
6. 目标为目标合约紧随其后的三个完整交易日，长度仍为 `15/17/19/21` 根。
7. 任何输入流都不能包含目标起点后的数据。

初始版本不要求一个目标同时拥有近月和远月。已选择的最近邻必须具备完整上下文；否则该案例不能进入 P1 的配对比较。这样无需向 tokenizer 填入会参与自注意力的伪 K 线。

P1 的主要配对比较只纳入恰好选出一个有效最近邻的案例；没有有效邻居的案例仅用于验证 target-only fallback。未来若评估多个邻居，仍从同一排序候选集中按顺序取前 `N` 个，并把 `N` 作为单独实验变量。

同一个预测时刻可以产生多个目标合约案例，但这些案例高度相关；训练采样、验证汇总和 bootstrap 都必须按预测时刻分组。

## 6. 上下文长度策略

先做覆盖审计，再决定 `L`：

- 分别统计 `L=256` 和 `L=512` 时，各品种、邻居方向（更早/更晚）、各时间折可构造的完整目标案例和最近邻配对案例数。
- 单合约基线与双合约模型必须使用相同 `L`、相同目标案例 key。
- 512 只有在每个 walk-forward fold 都保留至少 80% 的 256 配对案例、且更早/更晚两种邻居方向分层都非空时，才能作为主实验；否则以 256 为主，512 只作探索报告。
- 不在同一次正式比较中同时选择上下文长度、面板结构和损失权重。

256 根约覆盖数十个交易日，512 根约覆盖其两倍；更长上下文并不自动更好，它会减少新上市合约的有效样本。

## 7. 输入表示与归一化

### 7.1 六维合约流

每条存在的合约流保持形状：

```text
[batch, context_length, 6]
```

每条流分别经过同一个 Kronos tokenizer 和共享的 Kronos 编码权重。P1 只有目标流与一条最近邻流；模型输入不是一条 12 维 K 线。以后增加邻居时也不改变单流六维接口。

### 7.2 合同内归一化

每条流只用自己的上下文拟合归一化统计量，禁止使用未来数据。目标合约的未来标签使用目标合约自己的上下文统计量进行归一化和反归一化。

### 7.3 必须显式保留期限结构

各流独立标准化会消除绝对价格水平差异，因此仅融合标准化后的隐藏状态无法完整表达升贴水。首版双合约融合额外提供以下在预测时刻可计算的确定性状态：

- `log(neighbor_close / target_close)`；
- 邻居相对目标的有符号交割月份距离；
- 邻居存在掩码与目标/邻居角色嵌入；
- 最近五个完整交易日的邻居/目标成交量对数比。

这些状态只进入合约间融合层，不改变 Kronos tokenizer 的六维输入；它们用于恢复两条原始六维流之间会被独立归一化抹去的关系。第一轮不加入 OI、宏观数据或额外技术指标，避免无法归因。若以后允许多个邻居，融合器必须对邻居排列保持不变，期限方向由有符号月份距离表达。

## 8. 模型与训练阶段

### Phase P0：数据与目标单流基线

目的：隔离上下文长度本身的影响。

- 使用目标合约单流和 CE-only 损失。
- 在共同案例集合上报告 256 与 512；主 `L` 只按第 6 节的数据覆盖规则固定，不用方向指标挑选长度。
- 报告 zero-shot、CE-only、momentum、persistence 和 majority 基线。

### Phase P1：Pair Probe

目的：在不改完整生成器前，以最小变量验证一个最近月份邻居是否真的带来新增信息。

- tokenizer 和 Kronos 主干先冻结。
- 目标与最近邻分别编码，取得各自最后一个有效上下文隐藏状态。
- 将两个隐藏状态、期限结构状态、角色嵌入和存在掩码送入一个小型融合头。
- 使用同一融合头架构、同一参数量与同一训练协议比较；target-only 对照把邻居分支置为固定空表示并将存在掩码设为 0，不调用邻居 tokenizer：
  - `target_only_probe`：目标隐藏状态加空邻居分支；
  - `pair_probe`：使用目标、一个最近邻和期限结构状态。
- 主任务先固定为 Day3 方向分类；Day1/Day2 只作辅助报告，不在首轮增加新的损失权重。

只有 `pair_probe` 在严格配对案例上稳定优于 `target_only_probe`，才说明邻居信息本身有价值。此时仍不能推断“邻居越多越好”。

### Phase P2：单邻居条件路径生成

目的：让已经验证有效的一个最近邻信息影响目标合约的完整 21 根生成路径。

现有 `decode_s1` 只接受 token IDs，因此不能把 P1 的融合向量直接交给原生成接口。需要新增一个小型条件适配器：

1. 最近邻流经过共享编码器，并与确定性期限结构状态融合为固定的 `neighbor_condition`；
2. 适配器从 `neighbor_condition` 产生目标流的残差/FiLM 条件；
3. 条件在目标 token embedding 进入 Transformer 前注入，不改变 tokenizer，也不占用 512 根目标上下文；
4. autoregressive inference 的每一步复用同一预测原点计算出的 `neighbor_condition`；
5. 输出仍是目标合约的 s1/s2 token，损失先保持纯 token CE。

`neighbor_condition` 必须只由预测原点以前的邻居上下文与确定性期限结构状态计算。teacher forcing 中出现的目标未来 token 不得进入条件编码器。

训练顺序：

1. 冻结 tokenizer 和 Kronos 主干，只训练融合层及条件适配器；
2. 若内部验证改善，再解冻预测器最后少量层；
3. 不恢复 Phase 3 的方向辅助损失，不同时搜索新的 lambda；
4. checkpoint 仍按预先固定的目标合约路径指标选择。

只有单邻居 P2 也通过第 10 节门槛，才进入可选的 P2b 多邻居消融：保持其余设置不变，依次比较 `N=1` 与 `N=2`。不能直接把第二个邻居加入首轮正式实验。

### Phase P3：稳定性

仅在 P2（或可选 P2b）的最终候选达到验收门槛后运行三个固定 seed。未达到门槛则停止，不扩大融合层、上下文长度或损失搜索。

## 9. 数据划分与防泄漏

- 使用全局日历时间 walk-forward；同一预测日的所有目标合约必须进入同一 split。
- split 边界按完整 target 结束时间判定，并在相邻 split 之间清除至少三个交易日，避免重叠标签跨界。
- 邻居是否存在、选择顺序、有符号月份距离和期限结构状态都必须在预测原点确定。
- 每条流的归一化统计量只来自该流的历史上下文。
- 模型选择只能看 inner validation；最终时间段冻结后只评估一次。
- 因同一天多个合约和多个品种共享市场冲击，bootstrap 以交易日为基本重采样单位，而不是把每个合约案例视为独立样本。

## 10. 对照与验收门槛

正式比较必须使用相同的目标案例 key、相同 `L`、相同随机采样次数和相同时间折。

### P1 进入 P2 的门槛

- pooled Day3 balanced accuracy 相对 `target_only_probe` 至少提高 2 个百分点；
- 多数 walk-forward folds 同方向改善；
- 提升不能只来自一个品种或一种邻居方向，任一品种相对基线的退化不得超过 1 个百分点；
- 5 日和 10 日 block 的配对 moving-block bootstrap 均满足 `P(improvement > 0) >= 80%`；
- 若无一致改善，直接停止邻居条件生成开发。

### P2/P2b 进入多 seed 的门槛

- Day3 路径 balanced accuracy 相对相同 `L` 的目标单流 CE-only 至少提高 2 个百分点；
- 目标合约 Day3 return MAE 相对基线恶化不超过 2%；
- mean return-path correlation 至少达到 0.10，且各品种均为正；
- z-normalized DTW 相对基线至少降低 5%；
- 任一品种 Day3 balanced accuracy 相对基线的退化不得超过 1 个百分点；
- 改善不是由单个 fold 驱动。

这些是开发门槛，不代表可交易或前瞻有效。

## 11. 必须测试的边界场景

- 目标合约是最早交割月份：最近邻只能来自更晚月份。
- 目标合约是最晚交割月份：最近邻只能来自更早月份。
- 目标位于中间且两侧月份距离相同：必须按预先固定规则选择交割更晚的邻居。
- 只有目标合约满足上下文长度：不得伪造邻居流。
- 某个邻居在上下文中缺根：案例必须被拒绝。
- 两个合约代码年月顺序与字符串字典序不同：必须按解析后的交割年月排序。
- 预测日同一品种产生多个目标案例：它们必须进入同一 split 和同一 bootstrap 日块。
- 交割月份跨年，如 `2609` 与 `2701`：月份距离必须正确。
- 期限结构状态只能使用预测原点最后一根已完成 K 线。
- P1 的 target-only 和 pair 案例 key 必须完全一致。
- P2 在零初始化适配器、尚未解冻主干时关闭 neighbor condition，输出应数值回归到对应的 P0 目标单流路径；解冻主干后不再要求这一数值恒等。
- 生产预测没有有效邻居时必须路由到 P0 模型，不能调用只在配对案例上训练的 P2 模型。
- 可选多邻居实现中，改变邻居输入排列不能改变输出；删除无效/掩码邻居也不能改变输出。

## 12. 实施顺序

1. 建立活跃合约清单与安全拉取/归档命令。
2. 实现具体合约加载、交割年月解析、最近邻选择、时间对齐和配对案例审计。
3. 统计 256/512 的有效案例覆盖，冻结主上下文长度。
4. 重建目标单流 zero-shot 与 CE-only 基线。
5. 实现并运行 P1 Pair Probe。
6. 只有 P1 通过门槛才实现 P2 单邻居条件适配器与生成接口。
7. 只有单邻居 P2 通过门槛才评估第二个邻居；只有最优 P2 方案通过门槛才运行多 seed 和锁定时间段评估。

## 13. 主要风险与停止条件

- 当前服务无法补取已交割合约，初始训练样本可能不足；样本不足时优先持续归档，不用扩大模型掩盖数据问题。
- 独立标准化后的隐藏状态可能只包含形态信息，因此期限结构状态是邻居方案的必要组成部分。
- 相邻月份合约高度相关，最近邻可能没有增量预测力；P1 就是为低成本否证这一假设。
- 现有生成 API 不支持外部条件；P1 未通过前不投入 P2 改造。
- 多目标合约案例共享同日冲击，若按案例而非日期统计，会虚增显著性。
- 如果邻居只改善分类头、不改善目标合约生成路径，应明确判定“邻居分类有效、路径生成无效”，不得混合口径。

## 14. 本阶段明确不做

- 不使用连续合约或任何换月拼接。
- 不向单条 K 线 tokenizer 输入增加第七个市场字段。
- 不要求每个案例必须拥有三个合约。
- 不把多条合约流直接拼成 `6K` 维输入后重用原 tokenizer。
- 不在首轮加入 OI、宏观、新闻或大量技术指标。
- 不同时搜索上下文长度、融合结构、方向损失权重和跨品种共享方式。
- 不把当前活跃合约上的回测写成跨生命周期或可交易结论。
